# Pocketbase is wonderful
Having been a software developer for a long while, I've looked at several database solutions over the years. Usually it's the same idea of connecting to the database, loading some schemas, and doing the rest manually. It's a very longwinded process of writing code until your heart explodes. Don't get me wrong; I've done that countless of times myself. But when a simple application comes across the abyss that is my mind's eye of project ideas, it's often too much of a burden to write an entire database connection (usually MongoDB in my case) and associated interactors just to store two or three tables. So, eager to find a solution, a few years ago I stumbled upon [Pocketbase](https://pocketbase.io); a 'small but mighty backend in a single file.'

Pocketbase takes the edge off of the often complicated database logic that you'll ultimately end up writing in a normal codebase. With Pocketbase, everything from schemas to OAuth and mailing is handled in a single webpage-enabled executable that you host yourself (and yes, it _is_ a single file). Want to set up email verification using a Microsoft Exchange server as the outgoing mailserver? It's only a couple of clicks away. Looking to implement GitHub or GitLab OAuth integration in your app? Create the application on the OAuth provider's website, pop the info in Pocketbase, and the backend logic is ready to go. With Pocketbase, it's dead simple to create super duper complex applications without ever touching a single line of database logic. Everything is handled cleanly and efficiently by Pocketbase's internal code, all running locally on your server or hosting provider.

## What about AI?
It's the hot new thing these days, isn't it? I've certainly been confronted by AI over the past six months, and anyone who has spoken to me in that time will know that I do not enjoy AI, and that I do not advocate for the vibecoding trend everyone is following along with. AI is confronting me in my hobbies, at work, everywhere I go. There hasn't been a single day over the past six months where I _haven't_ heard or read about a new AI mishap that sent a company into millions of dollars in debt. The short of it is, I'm not a fan of AI. Luckily though, the authors of Pocketbase seem to feel the same way.

Recently, a warning was added to the readme file of the project, touching on the so-called AI-spam that was littering the pull requests section of the repository. The message reads:

> Due to recent LLM spam, PRs are temporary disabled and only existing collaborators can open a PR. If you stumble on a problem that you want to fix, please consider instead opening an issue or discussion with link to your fork (if not obvious - LLM contributions are not welcome). This status may change in the future in case GitHub finally decide to do something about the constant spam, or when I find time to move the project somewhere else.

After having looked at the closed pull requests of the repository, I understand their verdict. There are several closed pull requests marked as 'AI', each of them fixing things that aren't actually broken. It's nice to know that action has been undertaken against AI, but I also think that GitHub is ulimately at fault for not regulating these AI generated code contributions more effectively. There's undoubtedly still a lot of bugs to work out of the system with the rise of the AI landscape, but I think moderation is a good first step.

## What do I use Pocketbase for
ArcOS is the primary one. I promise not to make every article on my blog about ArcOS, but there's no denying that it's a great part of my development journey. I deployed Pocketbase three years ago for a tiny project, ArcRedirect-SvelteKit, which is essentially a URL-shortener project. Using Pocketbase for this means that I can easily add new redirects to the shortener without having to write an entire add/list UI beforehand. Pocketbase makes it super duper easy. The project itself just takes the ID from the URL, queries it to Pocketbase as a filter, and redirects to the URL that belongs to the name. It's blissfully simplistic.

In 2021 I started working on a suite of intranet applications for my family members at home to use. File management, music players, all kinds of things. The backend that I used to power this suite of around 10 applications, was Pocketbase. In fact, I say 'was', but it's been running perfectly for almost 5 years, without a hitch. That pocketbase database has been through countless versions and server deployments, and is still going strong after all this time. For a piece of beta software, Pocketbase sure is surprisingly robust.
